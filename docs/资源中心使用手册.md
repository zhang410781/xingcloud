# 资源中心使用手册

> 适用版本：资源中心统一模型上线版本
> 适用对象：平台管理员、资产管理员、运维负责人、项目负责人和值班人员

## 1. 资源中心解决什么问题

资源中心统一保存长期稳定的资源身份、归属、负责人、状态和关系，是平台中的资源事实源。它与其他模块的职责边界如下：

| 模块 | 主要职责 |
| --- | --- |
| 资源中心 | 保存物理机、虚拟机、K8S 集群与节点、数据库、中间件、应用服务等稳定资源 |
| K8S 集群管理 | 实时查看和操作 Namespace、工作负载、Pod、Service、存储、配置等 Kubernetes 对象 |
| 任务中心 | 保存执行目标、凭据引用和任务参数，不作为资源身份来源 |
| 业务上下文 | 为智能助手、巡检和精准研判选择数据源、可选集群及资源范围 |
| 告警中心 | 将外部或平台告警匹配到资源，并按资源负责人发送通知 |

Pod、Service、Deployment 等短生命周期对象不会进入长期资源清单。平台会将它们保存为带过期时间的运行时索引，用于告警关联和研判下钻。

## 2. 权限要求

| 权限 | 可执行操作 |
| --- | --- |
| `cmdb.ci.view` | 查看资源清单、详情、负责人、发现源和发现历史 |
| `cmdb.ci.manage` | 登记和编辑资源、配置负责人、执行自动发现 |
| `cmdb.topology.view` | 查看资源关系 |
| `ops.K8s.view` | 查看 K8S 集群和实时资源 |
| `ops.K8s.manage` | 登记、修改或删除 K8S 集群连接 |
| `ops.alert.manage` | 在告警详情重新匹配资源 |

权限由后端校验。页面未显示按钮时，应先检查当前角色是否具备对应权限。

## 3. 页面入口

登录平台后，从左侧菜单进入 **资源中心 > 资源中心**。页面提供四个视图：

1. **资源清单**：查看、筛选、登记和编辑稳定资源。
2. **自动发现**：查看 K8S 发现源、连接状态和最近错误，执行发现预览或立即发现。
3. **发现历史**：查看每次采集的新增、更新、未发现和失败结果。
4. **资源关系**：查看集群包含节点、应用部署到集群等长期关系。

页面顶部统计资源总数、使用中、异常、失联资源和发现源数量。任何接口加载失败都会显示明确错误提示，不会用空数据代替成功结果。

## 4. 手工登记资源

点击右上角 **登记资源**。当前支持手工登记：

- 产品、业务系统和应用服务。
- 物理机、虚拟机。
- MySQL、PostgreSQL。
- Redis、Kafka、RocketMQ。

### 4.1 通用字段

| 字段 | 说明 |
| --- | --- |
| 资源类型 | 决定资源分类和扩展字段 |
| 资源名称 | 平台内用于识别资源的稳定名称，必填 |
| 显示名称 | 面向用户展示的名称，可与资源名称不同 |
| 环境 | 生产、测试、开发或未指定 |
| 状态 | 使用中、异常、疑似失联、已失联、已下线等 |
| 所属产品 | 用于产品维度筛选和告警归属 |
| 业务系统 | 资源所属的业务系统 |
| 业务上下文 | 可选；仅在智能助手、巡检或研判需要该资源时绑定 |
| 重要级别 | 低、中、高或核心 |
| 说明 | 记录用途、位置或管理备注 |

### 4.2 主机字段

物理机和虚拟机应填写主要 IP，可补充序列号和操作系统。建议同一台主机只登记一次；同一 IP 被多个资源使用时，告警匹配会标记冲突，不会自动选择其中一个。

### 4.3 数据库和中间件字段

数据库和中间件必须填写访问地址，可填写端口和版本。例如：

| 资源 | 地址 | 端口 |
| --- | --- | --- |
| Redis | `redis-prod.internal` | `6379` |
| MySQL | `10.20.1.15` | `3306` |
| Kafka | `kafka-01.internal` | `9092` |

地址和端口共同形成精确端点标识。同一主机运行多个实例时，告警携带 `IP:端口` 可以精确匹配；只有 IP 且对应多个资源时，平台会显示“匹配冲突”。

### 4.4 人工字段保护

人工编辑过的名称、归属、状态、IP 和扩展属性会被标记为人工维护字段。后续自动发现不会覆盖这些字段。资源详情中的 **最近变更** 会记录手工登记、手工修改和自动发现更新。

## 5. 接入 K8S 集群并自动登记节点

K8S 集群连接在 **平台管理 > K8S 集群管理** 中登记，不在资源中心重复录入。

1. 进入 K8S 集群管理。
2. 点击新增集群，填写集群名称、API Server 和 kubeconfig。
3. 完成连接测试并保存。
4. 平台自动为该连接创建资源发现源。
5. 返回资源中心的 **自动发现** 页面。
6. 先点击 **发现预览**，确认集群 UID、节点名称、IP 和数量。
7. 点击 **立即发现**，等待对账完成。

平台使用 `kube-system` Namespace UID 识别集群，使用 Kubernetes Node UID 识别节点。节点改名或 IP 变化不会重复创建资产。

自动发现采集以下节点信息：

- Ready 状态和 Node Conditions。
- 角色、InternalIP、Provider ID。
- Kubernetes、Kubelet、内核和容器运行时版本。
- CPU、内存和 Pod 容量。
- 标签、污点、操作系统和架构。

单个运行时 API 失败时，其他采集结果仍会保存，发现状态显示为 **部分成功**。节点一次或两次未返回时不会立即失联，连续三次未发现后才标记为 **疑似失联**。

## 6. 查看运行时对象

打开 K8S 集群资源详情，可以看到 Namespace、Deployment、StatefulSet、DaemonSet、Service 和 Pod 的当前数量。

这些对象只用于：

- 将 Pod 告警关联到所属集群。
- 为告警研判提供当前运行状态。
- 从资源中心下钻到 K8S 管理页面。

查看 Pod 日志、事件、YAML 或执行操作时，应进入 **平台管理 > K8S 集群管理** 并在页面内选择目标集群。

## 7. 配置资源负责人

负责人使用告警中心已有的接收人资料。配置前先进入 **告警规则 > 通知配置 > 接收对象**，维护姓名、手机号、邮箱和偏好渠道。

在资源清单中点击资源的 **负责人**：

1. 选择职责：运维负责人、项目负责人、产品负责人或值班人员。
2. 选择告警接收人。
3. 点击添加。

通知策略启用 **追加资源负责人** 后：

| 告警级别 | 追加负责人 |
| --- | --- |
| Warning | 运维负责人、值班人员 |
| Critical | 运维负责人、值班人员、项目负责人、产品负责人 |

上级资源负责人仅在启用“向下继承”时应用到子资源。例如产品负责人可以继承到属于该产品的应用或主机；子资源负责人不会反向应用到产品或集群。

## 8. 告警如何匹配资源

平台按以下优先级寻找唯一资源：

1. Kubernetes UID。
2. Zabbix Host ID。
3. Pod 名称、Namespace 和集群运行时索引。
4. 精确端点，例如 `10.20.0.50:6379`。
5. IP 地址。
6. 唯一集群名称。

在告警详情可以查看 **资源中心匹配** 和 **匹配依据**。

- **已匹配**：告警已关联唯一资源，可使用资源负责人通知。
- **未匹配**：告警没有提供可识别的 UID、IP、端点或对象名称。
- **匹配冲突**：告警信息对应多个资源，平台不会猜测负责人。

补录资源或修正标识后，在告警详情点击 **重新匹配**。该操作只更新资源关联和审计记录，不会重新触发告警或重新执行研判。

## 9. 绑定业务上下文

业务上下文不是资源登记的前置条件。只有以下场景需要绑定：

- 智能助手需要查询该资源的指标或日志。
- 集群或服务器巡检需要将该资源纳入范围。
- 告警精准研判需要关联资源、拓扑和负责人证据。

可以在登记或编辑资源时选择一个或多个业务上下文。K8S 场景还可以在 AIOps 配置中直接选择一个集群；服务器或纯日志上下文不要求绑定 K8S。

## 10. 资源关系与应用发布

资源关系视图展示长期关系：

| 关系 | 示例 |
| --- | --- |
| `contains` | K8S 集群包含节点 |
| `belongs_to` | 主机或应用属于业务系统/产品 |
| `deployed_on` | 应用服务部署到 K8S 集群 |
| `runs_on` | 组件运行于主机或节点 |
| `depends_on` | 应用依赖数据库或中间件 |
| `monitored_by` | 资源由数据源监控 |

应用发布成功后，平台会创建或更新应用服务资源，并建立到目标 K8S 集群的 `deployed_on` 关系。首次发现时间不会因后续同步而被覆盖。

## 11. 常见问题

### 11.1 新增集群后资源中心没有节点

依次检查：

1. K8S 集群连接状态是否为已连接。
2. 资源中心是否已出现对应发现源。
3. 发现预览是否能读取 `kube-system` Namespace 和 Node 列表。
4. 发现历史中的错误信息。
5. kubeconfig 是否至少具有 Namespace、Node、Pod、Service 和工作负载只读权限。

### 11.2 发现状态是部分成功

查看发现源的最近错误和发现历史摘要。部分成功表示集群与节点已经完成对账，但某一类运行时 API 读取失败。修正 RBAC 或 API 连通性后重新执行立即发现。

### 11.3 告警没有发送给负责人

检查：

1. 告警是否已匹配资源。
2. 资源是否配置了与告警级别对应的负责人。
3. 负责人是否关联启用的告警接收人。
4. 通知策略是否启用“追加资源负责人”。
5. 当前告警是否被静默、抑制、聚合或降噪；研判通知会跟随告警通知策略。

### 11.4 共享 IP 为什么显示匹配冲突

IP 不是绝对唯一身份，一台主机可能运行多个数据库或中间件实例。应让外部监控携带端口、Zabbix Host ID 或 Kubernetes UID，或者为不同实例登记可区分的端点。

### 11.5 可以删除自动发现的集群和节点吗

资源清单只允许直接删除手工资源。自动发现资源应通过停用发现源、下线集群连接或资源生命周期状态处理，避免破坏稳定标识和历史告警关系。

## 12. 旧资产数据迁移

旧 ConfigItem 和中间件资产不会随版本升级自动删除。上线后先执行预览：

```bash
python manage.py clear_legacy_asset_data
```

输出会说明拟删除数量，但不会修改数据。完成备份和资源中心验收后，管理员才能显式执行：

```bash
python manage.py clear_legacy_asset_data --confirm
```

清理命令不会删除任务执行目标、主机凭据、K8S 集群连接或资源中心数据。生产环境不得在未备份、未核对资源和未确认回滚方案时执行 `--confirm`。
