# 资源中心

> 状态：当前已实现

## 1. 产品定义

资源中心是稳定资源的统一事实源，负责资源身份、生命周期、负责人和长期关系。业务上下文只在智能助手、巡检和精准研判需要统一证据范围时绑定，不作为资源登记前置条件。

## 2. 资源类型

当前内置产品、业务系统、应用服务、物理机、虚拟机、K8S 集群、K8S 节点、MySQL、PostgreSQL、Redis、Kafka 和 RocketMQ。物理机、虚拟机、数据库和中间件支持手工登记；K8S 集群从平台管理接入，节点由 Kubernetes API 自动发现。

## 3. 自动发现

- 新增 K8S 集群后自动创建发现源，默认每 10 分钟对账。
- 集群使用 `kube-system` Namespace UID、节点使用 Node UID 作为稳定身份。
- 自动采集版本、角色、IP、操作系统、容器运行时、容量、标签、污点和 Conditions。
- Namespace、工作负载、Service 和 Pod 作为带 TTL 的运行时索引，不进入长期资产清单。
- 单类运行时 API 失败时保存其他结果并标记“部分完成”；节点连续三次未发现后才标记疑似失联。
- 人工修改的治理字段会锁定，后续发现不会覆盖。
- 资源详情展示最近的手工登记、手工修改、自动发现新增和字段更新记录；资源关系分别保留首次发现与最近发现时间。

## 4. 负责人和告警

资源可配置运维负责人、项目负责人、产品负责人和值班人员。告警通过 K8S UID、Zabbix Host ID、Pod 运行时索引、IP、端点或唯一集群名称匹配资源；端点包含端口时优先精确匹配，共享 IP 无法唯一识别时明确标记“匹配冲突”，不会把标识静默转移给后登记资源。在告警源的分级通知策略中选择“资源负责人”接收对象后，Warning 通知运维和值班负责人，Critical 还会通知项目和产品负责人。上级资源负责人只有启用“向下继承”后才应用到子资源；资源补录或标识修正后，可在告警详情点击“重新匹配”更新关联，不需要重建告警。

## 5. 资源关系

资源中心维护 `contains`、`deployed_on`、`runs_on`、`depends_on` 和 `monitored_by` 等长期关系。应用发布会更新应用服务资源并建立应用到 K8S 集群的 `deployed_on` 关系。

## 6. 与任务中心和 K8S 管理的边界

- 资源中心保存资产身份、归属和负责人。
- 任务资源保存执行地址、凭据引用和执行参数，不再承担资产身份。
- K8S 管理直接操作实时 Namespace、Pod、Service、工作负载、网络、存储和配置对象。
- 资源中心仅保存这些对象的短期索引，用于告警关联和研判下钻。

## 7. 迁移

旧 ConfigItem、中间件资产不会自动删除。管理员先执行 `python manage.py clear_legacy_asset_data` 查看数量，完成备份后再使用 `--confirm`。默认关闭旧 Host/ConfigItem 双向同步；回滚时可临时设置 `ENABLE_LEGACY_CMDB_SYNC=true`。
